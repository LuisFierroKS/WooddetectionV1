Clasificación Inteligente de Madera: YOLO & Android

Una guía metodológica y técnica detallada sobre la conversión del modelo de Deep Learning y su arquitectura de inferencia nativa en dispositivos móviles.

Metodología de Conversión y Preparación

Para transferir un modelo entrenado en servidores o GPUs a un celular de baja potencia sin sacrificar precisión, se debe realizar un proceso de optimización, compilación y serialización. Estos son los pasos exactos y los comandos aplicados:

Paso 1

Exportación de PyTorch (.pt) a formato universal ONNX

El modelo de entrenamiento original se guarda en formato best.pt (PyTorch). Dado que Android no puede ejecutar pesos directos de PyTorch de manera eficiente, primero se convierte a ONNX (Open Neural Network Exchange), un estándar de representación abierta para modelos de machine learning.

Comando de Exportación (Python):

Python 
from ultralytics import YOLO

# Cargar el modelo entrenado
model = YOLO('best.pt')

# Exportar a formato ONNX configurando la resolución a 480x480
model.export(format='onnx', imgsz=480, dynamic=False)

¿Por qué? Definimos imgsz=480 porque es la resolución optimizada del entrenamiento, y desactivamos la opción de dimensiones dinámicas (dynamic=False) para garantizar que la estructura del modelo TFLite final sea fija y rápida.

Paso 2

Compilación a TensorFlow Lite (.tflite)

ONNX representa el modelo como un grafo abierto, pero los procesadores móviles necesitan un formato binario ligero. Usamos la herramienta especializada onnx2tf para transformar el archivo ONNX a TensorFlow Lite, realizando optimización y plegamiento de constantes.

Comando de Compilación (Terminal):

Bash / Windows PowerShell 
onnx2tf -i best.onnx -o app/src/main/assets -n

¿Por qué? El parámetro -i indica la ruta del archivo ONNX de origen, -o define dónde guardar los archivos binarios directamente en la carpeta de recursos de la aplicación Android, y el indicador -n deshabilita los tests automáticos acelerando la compilación.

Paso 3

Extracción de Clases y Etiquetas

Un modelo de clasificación predice números de clase (ej. clase 0, clase 1). Para que el usuario final lea el nombre común o científico de la madera, debemos extraer el listado exacto en el orden correspondiente. Se extrajo la metadata del archivo original de entrenamiento para crear labels.txt.

Comando de Extracción (Python):

Python 
from ultralytics import YOLO

model = YOLO('best.pt')
# Imprimir y mapear el listado de nombres ordenados
for idx, name in sorted(model.names.items()):
    print(name)
💡
Reto Técnico Resuelto durante el Proceso: Incompatibilidad de NumPy 2.x

Durante la compilación en Windows, la herramienta onnx2tf fallaba con un error de deserialización de pickle (`ValueError: This file contains pickled (object) data`). Esto se debía a que NumPy 2.x (usado en Python 3.13) bloquea por seguridad la carga de objetos serializados sin permisos explícitos.

Solución: Se modificó la librería de compilación nativa en el sistema en `common_functions.py` para forzar np.load(f, allow_pickle=True) al cargar las imágenes de calibración. Con este ajuste se logró compilar el modelo de manera limpia.

Arquitectura del Software Android

La aplicación móvil está construida sobre arquitectura nativa Java en Android Studio. Sigue un modelo de capas donde la lógica de la interfaz de usuario se mantiene separada de los cálculos del modelo matemático.

Diagrama de Estructura y Flujo de Datos

1. Capa de Presentación (UI)

Configurada en MainActivity.java y activity_main.xml.

  • Recibe la interacción del usuario mediante botones cómodos y de gran área de pulsación (64dp de altura).
  • Utiliza los disparadores modernos de Android Jetpack (ActivityResultLauncher) para abrir la cámara nativa del celular o seleccionar fotos del almacenamiento, capturando la imagen directamente en memoria RAM como un objeto Bitmap.
  • Actualiza el porcentaje de confianza en una barra de progreso de tono verde orgánico en tiempo real.

2. Capa de Lógica y Procesamiento

Encapsulada en la clase auxiliar WoodClassifier.java.

  • Carga el archivo binario del modelo TFLite directamente desde la memoria de los activos de la aplicación (Assets) usando canales de lectura rápidos de archivo de Java (FileChannel.MapMode.READ_ONLY).
  • Inicializa el motor de inferencia de TensorFlow Lite configurado en **4 hilos de procesamiento (Threads)** de CPU móvil para optimizar la velocidad en procesadores multinúcleo de teléfonos inteligentes.

Estructura del Código en Gradle (build.gradle.kts)

Para soportar esta arquitectura, añadimos las librerías oficiales de bajo nivel de TensorFlow y la de soporte para imágenes en la configuración de dependencias de Gradle:

build.gradle.kts 
// Dependencias añadidas en el módulo :app
dependencies {
    // Motor básico de inferencia
    implementation("org.tensorflow:tensorflow-lite:2.16.1")
    // Librería de soporte para procesamiento de imágenes y buffers de tensores
    implementation("org.tensorflow:tensorflow-lite-support:0.4.4")
}

android {
    // Evita que el compilador de Android reduzca o comprima el archivo .tflite al empaquetar el APK
    aaptOptions {
        noCompress("tflite")
    }
}

Carga del Modelo y Flujo de Inferencia

El núcleo de la aplicación radica en cómo el modelo procesa matemáticamente la imagen. Aquí detallamos los pasos exactos del ciclo de vida de una inferencia desde que entra la foto hasta que se muestra el resultado en pantalla:

Fase 1

Preparación del Contenedor de Entrada (TensorImage)

La foto capturada en formato Bitmap de Android no se puede introducir directamente en el intérprete de C++. Debe cargarse en un contenedor de bajo nivel estructurado como una matriz tridimensional en punto flotante (`FLOAT32`).

Java 
TensorImage tensorImage = new TensorImage(DataType.FLOAT32);
tensorImage.load(bitmap);
Fase 2

Pipeline de Preprocesamiento de Imagen

Para asegurar que la imagen de entrada tenga exactamente las mismas características con las que se entrenó la red neuronal YOLO, aplicamos un flujo de trabajo encadenado:

Java 
ImageProcessor imageProcessor = new ImageProcessor.Builder()
        // 1. Redimensionar a la resolución esperada por el modelo (480x480)
        .add(new ResizeOp(480, 480, ResizeOp.ResizeMethod.BILINEAR))
        // 2. Escalar valores de color enteros [0, 255] a floats [0.0, 1.0] (255 - 0 / 255)
        .add(new NormalizeOp(0.0f, 255.0f))
        .build();

TensorImage processedImage = imageProcessor.process(tensorImage);

¿Por qué? Si omitiéramos la redimensión, el intérprete lanzaría una excepción por disparidad de tamaño. Si no normalizáramos a base `[0.0, 1.0]`, la red recibiría valores saturados (fuera de escala) y las predicciones serían erróneas.

Fase 3

Inferencia en el Intérprete y Búfer de Salida

La salida del modelo YOLO de clasificación es un tensor plano de tamaño `[1, 35]`, que representa el porcentaje de probabilidad de las 35 especies de madera. Preparamos un buffer de memoria de tamaño fijo (`FLOAT32`) para recibir esta salida directamente desde la inferencia de C++:

Java 
// Crear buffer de salida para recibir 35 probabilidades
TensorBuffer outputBuffer = TensorBuffer.createFixedSize(new int[]{1, 35}, DataType.FLOAT32);

// Ejecutar la inferencia en CPU móvil
interpreter.run(processedImage.getBuffer(), outputBuffer.getBuffer().rewind());
Fase 4

Post-procesamiento: Extracción del Resultado Más Probable

Una vez ejecutada la inferencia, el buffer de salida se llena con 35 números decimales correspondientes a la confianza del modelo para cada madera. El programa recorre este listado para encontrar la posición (índice) que contenga la probabilidad más alta (valor máximo) y busca su nombre en el listado de etiquetas.

Java 
float[] outputArray = outputBuffer.getFloatArray();
int maxIdx = -1;
float maxVal = -1.0f;

// Buscar el valor máximo en la predicción
for (int i = 0; i < outputArray.length; i++) {
    if (outputArray[i] > maxVal) {
        maxVal = outputArray[i];
        maxIdx = i;
    }
}

// Obtener nombre de la madera correspondiente
String nombreEspecie = labels.get(maxIdx);
